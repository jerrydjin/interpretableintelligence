Find out why your robot policy failed, and whether you're fooling yourself.

For teams training robot policies and world models who need to know why a rollout went wrong, not just that it did.

Run `ii` on your policy.

What you get today

ii is free and local. ii run captures a layer, trains an SAE and scores features on the adapters that ship (fake, vjepa2, hf, groot); ii view opens the run; ii validate checks it. ii rollouts compares baseline and intervened task success with matched random-feature controls, on the synthetic reacher today; GR00T joins once it lands.

Proof

Feature 720 tracked failures, and turning it off dropped success from 39/75 to 1/9. Turning off random features caused falls too in 5 of 20 runs. `ii` makes you run that control before calling a feature real.

Run with the repo's GR00T ablation runner (ablate_v9.py), 641 rollouts. Label: Tested: no causal effect found. Results.

On V-JEPA 2, loss-based scores couldn't tell a trained SAE from a random one — so that control is now the bar.

Quickstart

uv sync
uv run ii try

ii try writes practice clips and runs the pipeline on the fake model.

  • ii try — New here? Start with this. Finds features in a small practice model and opens the playground.
  • ii run — Capture, train, extract features, score what is missing, then serve the viewer.
  • ii view — Start a local viewer for a run folder and open it in a browser.
  • ii rollouts — Compare baseline and intervened task success on the synthetic reacher. Resume skips episodes already written.
  • ii validate — Validate a run folder against the schema.

The rest of the commands are in the README.
