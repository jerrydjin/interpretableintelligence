# GR00T v9: parallel LIBERO env pool (2026-11-10)

## Design
- `physint_inproc_v9.run_pool(ctx, jobs, on_done=...)` starts N **spawned** worker processes. N is `GROOT_N_ENVS`, or by default min(cpu-1, 8), capped at (free RAM - 2 GB) / `GROOT_WORKER_GB` (2.0; a measured worker RSS is about 1.9 GB). Each worker owns a LiberoEnv with its own MuJoCo/EGL context and inherits `MUJOCO_GL`.
- Protocol: one message per **chunk**, not per step. The main process sends k ≤ 16 post-processed actions. The worker reads the sim state before each step (`read_sim`), steps, stops on success, term, trunc or T, and replies with the per-step sim arrays plus the next canonical obs. The main process does `build_policy_obs → predict_action_chunk → transition → postprocess_action` exactly as `v8.run_episode` does, then starts the next job in a slot when its episode ends.
- Noise: GR00T draws one `sample_noise((B,40,132))` per chunk. v9 routes it through a per-episode `torch.Generator(seed)` on the policy device, one (1,40,132) draw per env. That is the same stream v8 got from `torch.manual_seed(seed)`; the gap is 0.0 on CPU, and the notebook prints the CUDA check. It raises if the routed noise is not used exactly once per predict.
- Hook: `BlockTap` on `transformer_blocks.{LAYER}` requires exactly `num_inference_timesteps` calls per predict. It keeps the last call (the final denoise step) and splits [B, n_tok, D] back to each env with `x[b]`. Rows are then saved through v8's `_save_episode`, so the layout is the same as v8.
- Predict: `GROOT_BATCH_PREDICT=0` (default) makes one predict per env. That is bit-identical to sequential, and per-chunk IPC keeps the GPU from being the bottleneck at N ≤ 8: at 0.26 s per predict against 4.3 s per 16-step chunk, the GPU is busy about 48% at N=8. `=1` concatenates envs whose preprocessed tensors have identical shapes. This collation is bit-identical to the processor's own B=2 batch. It is used only after `verify_batched_predict` (batched vs single on the same obs and noise seeds, max |Δ| below `GROOT_BATCH_TOL`, default 2e-2) passes; otherwise it falls back to per-env. Batched fp16 kernels differ from B=1 in the last bits, and the closed loop amplifies that, so batched episodes are not bit-reproducible.
- **Fresh env per episode** (`GROOT_FRESH_ENV=1`). On a reused LiberoEnv, each hard reset moves `flat_stove_1_main` by 1.2–1.4 cm even with identical seeds and init state, measured on the box. v8 episodes therefore depended on the episodes that ran before them on the same env. A fresh env reproduces exactly across processes and orders, at a cost of about +1.5 s per episode.
- Probe: 20 episodes per task (`GROOT_PROBE_N`), seeds 10000+k with init k (same as v8). It resumes by episode index. It picks the task nearest 0.5 (ties go to 614), and reports Wilson 95% CI and `in_30_70`. Capture is the same as v8 (seed 20000+i, init i % n_init; n_init comes from a worker), and `manifest.runner` holds the pool stats.

## Per-pot failure detector (2026-11-10, rule `pot0-v1`)
- `v9/pot_events.py` (numpy only) is the single implementation, used by `physint_inproc_v9.label_episode` in capture and by the offline relabel `/workspace/runs/groot-1028-v9-n100/tools/derive_pot0_fail.py`.
- Why: `v8.derive_failure` judges a drop on the object nearest the EEF. On task 1028 it labelled pot 1's normal placement on the stove as a `drop` in 37 of 40 cases.
- What it does: computes per-pot lift / release / placement events from obj_pos, gripper_width and eef distance. Lift is more than 2 cm above the start. Release is gripper reopening or a confirmed separation. Off-stove is judged where the pot comes to rest, and the stove region is an xy box (`STOVE_REGIONS["KITCHEN_SCENE8"]`). It then labels the episode on pot 0 (moka_pot_1): `lifted_not_placed` / `never_grasped` / `pot0_placed_other_failure` / `empty_grasp`, with `fail_pot`, `fail_subkind`, `fail_rule`, the `pot0_*` anchors and `pot1_events`.
- Kept: `fail_kind_active` / `fail_t_active` (v8's label) and `failure_details` (v8's details).
- Fallback: tasks that are not a KITCHEN_SCENE8 moka-pots-on-the-stove task, or that have other object names, keep v8's label (`fail_rule` says so). The box was measured on 1028 only. 614 (view 0_0_100_0_0, initstate 229) is the same scene, so it gets the same box, but nobody has checked that against 614 successes yet. Labels only; probe, early stopping and capture data are unchanged.
- Regression: `tests/test_pot_events.py` replays the 100 recorded traces and requires the relabel in `episodes.jsonl` exactly. It also requires the v8 active label to be reproduced, and no `lifted_not_placed` fail_t within 16 steps of a pot-1 release or placement.

## SAE feature-ablation runner (2026-11-10, `ablate_v9.py`, plan `groot-ablate-plan-v1`)
- **Run it:** `ii rollouts --policy groot-1028` (`docs/groot-rollouts-verify.md`) calls `ablate_v9.run_ablation`. Knobs read by the runner: `GROOT_ABLATE_ONLY` (e.g. `baseline,arm-A`), `GROOT_ABLATE_OUT`, `GROOT_ABLATE_SAE`. It resumes from the per-condition `episodes.jsonl`. Plan and folder layout: `/workspace/runs/groot-1028-v9-ablate/README.md`.
- **run_pool changes (backwards compatible; the probe and capture paths are unchanged):**
  - `next_job=` is a scheduler callback, asked whenever a slot is free.
  - `editor=` is a forward-hook editor that gets `begin([job.meta["edit"] per batch row])` / `end()` around every predict. The editor is registered before the capture tap. Its per-episode stats end up on `Episode.edit_stats`.
- **Hook:** `LatentAblator` edits only at the final denoise step by default (`denoise_steps: "final"`; the SAE was trained there). It raises if the block fires a number of times other than `num_inference_timesteps` per predict, or if the recon-only path changes a single bit.
- **SPRT stop rule:** stop on H1 of either test, or on H0 of both (Sobel–Wald). With p0 0.56, p1 0.86 / 0.26 and α=β=0.05, the literal "stop when either test decides" could never return rise or fall, because the other test always accepts H0 first. That rule is kept as `stop_rule: either_test_decides` for checking.
- **Tests:**
  - `tests/test_ablate.py` (pytest) covers the hook arithmetic, the identity path, the final-step gating, the SPRT bounds, the paired delta, the schedule and resume.
